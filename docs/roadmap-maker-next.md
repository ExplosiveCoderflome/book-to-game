## 1. 一句话目标与成功标准

### 1.1 一句话目标

> 把 book-to-game 从「本机作者壳里能试玩」推进成 **文字版 RPG Maker**：用 **想法或对照小说 + AI** 快速拉出主线路，用内置 Substrate / Catalog / 建筑·物品 / HTTP·MCP **搭得住**，最终 **打出别人能打开的可玩文字游戏**——成品局内仍可接 AI（旁白 / 提案），**状态只经规则端口**。

### 1.2 成功标准（整条路线走完时）

| # | 可感标准 | 反例（不算成功） |
|---|---|---|
| 1 | **Maker 感**：作者能说「我丢想法/小说 → 有主线路草稿 → 补填充/绑定 → 发布」 | 只能手搓空图，或生成结果无法进试玩 |
| 2 | **搭得住**：主线路 + 商店/补给/任务/遭遇等桩能挂在同一 Substrate 上跑通 | 生成出一堆文案却点不动；或另起平行 runtime |
| 3 | **玩得出 / 交得出**：不进完整作者工作台，也能开一局已发布版本并走完 Perceive→Feedback | 只能在编辑器里点「试玩」；外人打不开 |
| 4 | **AI 可接且诚实**：作者时提案 / 玩时旁白·propose；**不** mutate session | 旁白当 delta；LLM 直写 SQLite |

编辑是手段；**交付可玩游戏**才是目的。

## 2. 现状与缺口（对照定位三句话）

### 2.1 与 P0–P2 的关系

| 代号 | 含义 | 状态 |
|---|---|---|
| **P0–P2** | 工作台内玩法闭环切片（反馈壳 → 开放填充 → 遭遇桩） | **已落地**（P1/P2 有条件通过） |
| **M0+** | Maker 产品化路线（生成体验 · 搭建加速 · **可交付壳**） | **本文**；接在 P2 之后，**不重做** P0–P2 |

P0–P2 证明「局里好玩」；M 期证明「工具能成局、成品能交出去」。

### 2.2 已落地（不要当没做）

| 能力 | 证据 / 备注 |
|---|---|
| 试玩反馈壳 | P0：HUD / 代价 / delta / 结局差异 |
| 开放填充可玩 | P1：shop / supply / quest（+ 有数据才交付） |
| 遭遇可玩桩 | P2：交锋/撤离 · loot 确定性 stub · Boss 同形无血条 |
| 生成改编 | Jobs / 草稿提交；人审后进 games/worlds |
| 发布固定版本 | `GameRevision` / `WorldRevision`；试玩只读 revision |
| 工作台内试玩 | sessions / adventure-sessions |
| 玩时 AI | narrate / propose-act（prompt-only；不提交状态） |
| 外接 Agent | HTTP · MCP 共用命令表 |
| Catalog 底座 | 数值模板 · 地图/建筑库 · 物品目录（形状 vs 世界绑定） |

软缺口（后置，不挡 M 期主线）：HUD「银两」vs 花费「通货」文案；截图包补齐；作者地图填充放置 UX（G1）。

### 2.3 缺口表（按定位三句话）

| 定位句 | 现状 | 主要缺口 |
|---|---|---|
| **生成快** | 有改编任务与提案；主线路「Maker 一键成局」感弱 | 想法/短设定入口；主脊+有效岔路的结构化产出；与 rubric D1/D4 对齐的生成门禁；一键落到可试玩草稿 |
| **搭得住** | Catalog + fill 桩 + API/MCP 齐；作者放置/绑定 UX 仍夹具向 | 放置 UX；真价/loot 绑定表单；「生成结果 → 填充/货架」一条龙；题材包默认内容 |
| **玩得出 / 交得出** | M1 `/play` 玩家壳、M1b HTML/EXE 离线交付已落地 | 播放器重编、导出包体积优化与持续打包回归；公网权限与发行后台仍后置 |

## 3. 原则（全程锁定）

| # | 原则 |
|---|---|
| 1 | **五层分离**：Substrate 真相 · Catalog compile-down · AI 只建议/映射 · UI 不发明语义 · Transport 只转发 |
| 2 | **AI 不 mutate session**：玩时旁白/提案不得当 delta；写操作只经 `sessions` / `adventure-sessions` / 草稿端口 |
| 3 | **一套 runner**：禁止按口味/题材分叉 runtime；口味用模板切换 |
| 4 | **交付优先于玩法扩容**：在「交得出一局」之前，不优先开任务图引擎 / 交涉系统 / 完整战斗 |
| 5 | **流程**：策划确认切片 → UI 界面规划（需界面时）→ 确认后再交 Coder；纯后端/文档小补可不经 UI |
| 6 | **默认不 commit/push**，除非用户明确要求 |
| 7 | **小说忠实是加分项**；可玩与可交付优先（对齐 playtest-rubric） |

## 4. 分期路线图（M0–M5）

每期均含：目标一句 · 可感 · In/Out · 依赖 · 验收一句。  
玩法深化（任务图、交涉、放置加深）标为后置/可选，**不抢**交付与 Maker 主路径。

### M0 · 定位对齐与软缺口分流（薄期 · 可与 M1 并行文档）

| 项 | 内容 |
|---|---|
| **目标** | 把「Maker + 可交付」写进产品默认叙事；软缺口分流，避免再排成「只加深玩法」 |
| **可感** | 文档与路线以交付为准；银两/通货等文案债进清单，不挡主线 |
| **In** | 本文定稿；player-loop / extensibility 索引指向 Maker 目标；软缺口 backlog（文案 · 截图 · G1） |
| **Out** | 新玩法 runtime；大改架构 |
| **依赖** | 用户确认本文 |
| **验收** | 用户点头：下一刀按 M 期而非再开一个纯玩法 P3 |

### M1 · 可分享 / 纯玩家最小交付（**必须期**）

| 项 | 内容 |
|---|---|
| **目标** | 已发布 `GameRevision` / `WorldRevision` 能在**不进完整作者工作台**的情况下开一局并走完核心闭环 |
| **作者可感** | 「发布 → 得到可给别人玩的入口/包」 |
| **玩家可感** | 打开壳 → 选/载入已发布版本 → Perceive→Act→Feedback（HUD/代价/delta 仍在） |
| **In** | 纯玩家路由（**先做**同宿主 `/play/...`，Q2=C）；只读 revision；开局/继续/结束；复用既有 sessions·adventures 端口；导出包属 **M1b**（见 §7） |
| **Out** | 公网多租户 · 账号体系 · 应用商店上架 · 加密 DRM · 完整发行后台；重做玩法 |
| **依赖** | P0–P2 反馈壳；已有 publish |
| **验收** | 陌生人（或第二个浏览器配置）**不打开编辑器**也能打完一局演示内容并说出选择与代价 |

### M2 · 想法 / 小说 → 主线路生成更 Maker（**必须期**）

| 项 | 内容 |
|---|---|
| **目标** | 作者用**一句话想法**或**对照小说选章**，生成**可审阅的主线路草稿**（推进脊 + ≥N 有效岔路骨架），一键进入可试玩路径 |
| **作者可感** | 「像 RPG Maker 新建工程：设定 → 生成主线 → 我改几处就能试」 |
| **玩家可感** | 生成局开局有冲突焦点；选项去向不同（对齐 D1/D4 软/硬门禁信号） |
| **In** | 想法入口（短设定表单）；主脊+分支结构提案；人审 accept → 草稿；与既有 generation / games·worlds 端口咬合；生成结果可对照 rubric 信号 |
| **Out** | 无人审直发正式版；AI 直写已发布 revision；保证原著逐句忠实；完整开放地图一次生成到可发行 |
| **依赖** | 既有 Jobs / 模型设置 / 草稿校验；M0 叙事对齐 |
| **验收** | 作者从空/短想法出发，**≤约定步数**得到可发布试玩的一局（故事或开放选一边做深，另一边可浅） |

### M3 · 搭建加速（Catalog · 放置 · 绑定一条龙）

| 项 | 内容 |
|---|---|
| **目标** | 让「生成出来的骨架」快速挂上商店/补给/任务/遭遇等**已有桩**，少靠手写夹具 |
| **可感** | 作者放置 UX（G1）；真价/loot 绑定表单；AI propose-fill / shelf 接受即 compile-down |
| **In** | 地图填充放置最小 UX；绑定 UI（resourceId / itemId / loot）；提案→放置流水线；演示「想法→主线→填充→试玩」脚本 |
| **Out** | 跨项目资产市场；完整任务图编排器；新经济仿真 |
| **依赖** | P1/P2 玩时桩；M2 主线路草稿可消费 |
| **验收** | 不靠手工 JSON 夹具，作者能在工作台内放齐至少 shop+encounter 并试玩通 |

### M4 · 成品内 AI 体验打磨（可选加深）

| 项 | 内容 |
|---|---|
| **目标** | 纯玩家壳内旁白/提案体验稳定、可关、可审计；作者可配置「本局是否允许玩时 AI」 |
| **可感** | 玩家壳有旁白开关；提案失败有诚实空态；不出现「AI 改了存档」幻觉 |
| **In** | 壳内 narrate/propose 入口；权限与模型配置边界（本机沿用设置）；telemetry/日志不泄密钥 |
| **Out** | AI 当主持人改结局真值；多模型热切换平台产品化 |
| **依赖** | M1 玩家壳；既有 play adapters |
| **验收** | 关闭 AI 仍可完整可玩；开启 AI 只增文案/建议，存档 diff 可证明无规则外写入 |

### M5 · 玩法深化（后置 · 可选 · 不抢 M1/M2）

| 项 | 内容 |
|---|---|
| **目标** | 在「交得出 + 生成得快」之后，再加深局内策略感 |
| **候选（择一或切片）** | 任务交付/奖励图浅层 · 交涉/关系旗 · 遭遇策略差加深 · 题材包默认内容 · 作者「循环体检」面板 |
| **In** | 单独立项切片文档；仍 compile-down；不新开战斗页 |
| **Out** | 像素地图 RPG Maker 克隆；实时战斗；放置 idle；parser IF 主循环 |
| **依赖** | M1 交付已过；建议 M3 搭建体验至少可用 |
| **验收** | 另文定义；默认**不**自动开工 |

## 6. 明确非目标（本路线图锁定）

| 非目标 | 说明 |
|---|---|
| 完整像素图 / 瓦片 RPG Maker 克隆 | 我们是**文字**游戏 Maker |
| 实时战斗 / 回合制血条仿真 / 装备槽 RPG | 与 player-loop 全局非目标一致；遭遇保持桩级 |
| 放置 / 挂机 idle 默认循环 | 禁止 |
| 公网多租户 · 账号 · 商店上架 **一期做完** | M1 只做本机/同宿主最小分享 |
| 自由文本 parser 作主循环 | 禁止；提案须经规则端口 |
| AI 直写存档 / 无人审发布正式版 | 禁止 |
| 按题材分叉 runner | 禁止 |
| 把 P0–P2 推倒重做 | 禁止；只接壳与生成 |
| 冒险经历自动改写成小说 | 后置且另文；非 M1–M3 |
