# 图像资产切片：开发过程中生成场景图、角色图（策划草案）

> 状态：2026-11-10 用户在「游戏引擎」群提出：纯文字太单调，要在开发过程中引入出图（场景图、角色图等）。策划草案，待用户确认 → UI 规划（须用户确认）→ Coder。排在「游戏生成主线打通」之后，不打断主线。未 commit。
> 承接：`agent-engine-spec-v0.md`（四层、积木、检查）、现有 `building-image.ts` / `MapImageProvider`（出图端口已有雏形，只用于建筑与地图）。

## 0. 一句话

出图是**制作期**的事：Agent 搭好世界后，按「美术设定」给场景、角色、关键事件出图，作者审过后**打进包里**；玩家玩的时候不现场生图，离线照样有图。图只负责呈现，不碰任何状态。

## 1. 为什么、做到什么程度

- 目标：让玩家每到一个地方「看得见」，遇到关键人物「认得出」，关键时刻有一张记得住的图。
- 不做：动画、立绘换装、地图美术重做、玩家端实时生图（放 AI 接入点后置）。
- 原则：**宁少而准，不多而乱**。一张风格统一的好图胜过十张风格打架的图。

## 2. 资产种类（第一版）

| 种类 | 挂在哪 | 用在哪 | 第一版数量（S 档 / M 档） |
|---|---|---|---|
| 封面 `cover` | manifest | 开始页、分享 | 1 / 1 |
| 场景图 `scene` | `locations[].art` | 进入地点时的页头横图 | ≤8 / ≤16 |
| 角色像 `portrait` | `characters[].art` | 对话、剧情卡里人物出场 | ≤6 / ≤12 |
| 表情差分 `portrait.moods` | 同上 | 喜/怒/悲等，按状态切 | 每角色 ≤3（只给主角色） |
| 事件图 `cg` | `storylets[].art` | 关键剧情卡（转折、高潮） | ≤4 / ≤10 |
| 结局图 `ending` | `endings[].art` | 结局页 | 每个结局 1 张，可共用 |
| 图标 `icon` | 物品、建筑（已有端口） | 列表、商店 | 沿用现有，不在本期扩 |

数量上限写进积木参数，作者可调，但超过档位上限要显式确认（成本）。

## 3. 一致性：美术设定（art bible）

这是整件事成败的关键。没有它，每张图风格不同、角色每次长得不一样。

- 每个世界一份 `art.json`（世界包新文件），Agent 在出第一张图之前必须先写好：
  - `style`：画风一句话（如「水墨淡彩，留白多，偏冷色」）、媒介、时代、色板（3–5 色）、禁用元素。
  - `aspect`：场景 16:9、角色 3:4、事件图 16:9、封面 3:4。
  - `negative`：统一的负面描述（不要文字、不要水印、不要现代物件等）。
- **角色设定卡**：每个要出图的角色先出一张「标准像」，作者确认后锁定，作为后续表情差分和事件图的参考图；角色外貌描述（发型、服饰、标志物）写进 `characters[].look`，所有含该角色的图都自动拼进提示词。
- **种子与提示词留档**：每张图记录 provider、模型、种子、最终提示词、参考图 id，可复现、可重出。
- 风格模板：按爽感画像给 4–6 个默认风格（仙侠水墨、武侠工笔、都市写实、经营暖色手绘、悬疑暗调、像素复古），作者可选可改。

## 4. 数据契约（建议，交 Coder 细化）

- 世界包新增 `assets/` 目录与 `art.json`；`assets/manifest.json` 列每张图：`id` `kind` `file` `w` `h` `bytes` `hash` `prompt` `seed` `provider` `refs[]` `status`（draft/approved/rejected）。
- 内容侧只引用 id：`locations[].art: "scene_ferry"`、`characters[].art: {base, moods:{sad,angry}}`、`storylets[].art`、`endings[].art`。
- 条件变体沿用统一条件语法：`art: [{when:[…], id:"scene_ferry_night"}, {id:"scene_ferry"}]`，第一个成立的生效（同 K15 textVariants）。
- **纯呈现**：图不进存档，不影响模拟、不影响确定性；缺图时显示文字，不报错不卡流程。

## 5. 制作流程（Agent 视角）

在现有「画像 → 积木 → 配置 → 内容 → 体检 → 修」之后插入美术段：

1. **写美术设定**（art.json + 角色 look）——作者确认（一次）。
2. **出资产清单**：Agent 按 §2 上限和剧情重要度挑出要出图的地点、角色、剧情卡，附理由。作者可删改。
3. **出角色标准像** → 作者逐个确认锁定。
4. **批量出场景、事件、结局图**（并发），带参考图。
5. **自动检查**（§6）→ 不过的自动重出，单张最多重出 2 次。
6. **作者审图**：网格一页看完，逐张 通过 / 重出 / 删；未通过的图不进包。
7. **打包**：压缩、嵌入、出包体报告。

作者可以随时跳过美术段，纯文字游戏照样能发布。

## 6. 检查（并入发布门槛）

| 检查 | 级别 |
|---|---|
| 内容引用的图 id 都存在且 approved | error |
| 单张超过体积上限（场景/事件 ≤180KB，角色 ≤120KB，webp） | 自动压缩，仍超则 error |
| 整包体积超过预算（单文件 HTML 默认 ≤12MB，手机可开） | error |
| 图里有可读文字/水印（OCR 检测） | warning，默认重出 |
| 同一角色多张图外貌不一致（与标准像比对，模型打分） | warning，交作者 |
| 未成年人不当内容、真人肖像、知名作品角色直接复刻 | error |
| 只有部分地点有图（覆盖率 <60%） | warning（避免有的有图有的没图显得残缺） |

## 7. 玩家端呈现（需 UI 出规划，经用户确认）

只提需求，不定界面：
- 进入地点：页头横图，文字在下，不遮正文。
- 人物出场：小头像跟在说话人旁；表情按状态切。
- 关键事件：事件图在剧情卡顶部，可点开看大图。
- 结局页：结局图置顶。
- 手机 375×812 下图片不挤压正文，首屏仍能看到第一段字。
- 可选「图鉴」页（已见过的图），第一版不做。
- 设置里给「纯文字模式」开关（省流、偏好）。

## 8. 成本与供应商

- 出图走现有图像端口（`MapImageProvider` / `BuildingImageProvider` 同一模式），新增统一的 `ArtImageProvider`，UI 与目录不直连厂商。
- 每局出图设预算（张数 + 金额），超预算停下问作者。
- 重出、删除都计数，报告里写清本次花了多少张。

## 9. 第一版范围

- In：art.json + 角色 look、cover/scene/portrait/cg/ending 五类、条件变体、自动检查、审图网格、打包压缩、HTML 导出带图、用一个新生成的小样本验收。
- Out：表情差分以外的立绘系统、图鉴、玩家端实时生图、exe（暂停中，恢复后补）、地图美术。
- 《寿灯》金样本不改；可另做一份「寿灯·带图版」作为第二验收样本（需用户同意）。

## 10. 验收条

1. 一个点子生成的游戏，走完美术段后：封面 1、场景 ≥5、角色 ≥3、事件 ≥2、每个结局有图。
2. 同一角色在 3 张以上图里，作者肉眼认得出是同一个人；整套图风格统一。
3. 单文件 HTML ≤12MB，375×812 离线打开，图正常显示，首屏能看到正文。
4. 关掉「显示图片」后游戏完全可玩，存档与无图版互通。
5. 图里无文字乱码、无水印；检查报告全绿。
6. 策划亲玩一遍，确认图在加分而不是打断阅读。
