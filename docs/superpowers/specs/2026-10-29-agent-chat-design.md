# Agent 对话入口与操作编排

用户指出此前交付缺少实际对话入口，确认先前“Agent完成”范围不完整。本轮补齐用户可直接使用的聊天及工具操作，保留未提交的修复候选功能，由root独立完成，不委派。

## 用户流程

主导航新增显式“Agent 对话”。左侧会话列表、新建、刷新恢复；主区连续对话、工具调用状态及操作确认卡、输入和发送。沿用模型设置，未配置时提供前往设置入口。对话及按需读取的本地资料会发送至配置的模型，页面明确说明。

模型可自动查询原作目录/证据、任务、草稿、体检和候选，也可运行确定性的校验/模拟/候选生成。修改草稿、创建生成任务、重试/取消、确认规划、应用候选、发布必须形成持久待确认操作，显示目标、参数与差异摘要，作者点击确认才执行。模型不能直接调用确认接口、设置密钥、读任意文件或修改数据库。复用HTTP/MCP共用命令，不另写游戏规则。

## 状态及恢复

SQLite保存会话、消息、模型原生tool_calls和逐条工具回执、待确认操作及执行结果。发送使用requestId去重并校验内容一致性；CAS版本保护阻止并发对话覆盖。模型轮次最多4轮，每轮最多4个工具。结果截断明确标识，不把部分JSON当完整草稿。只有白名单工具对模型开放。

操作参数在提议时解析并固定。涉及已有任务的操作额外记录updatedAt，确认时校验；草稿/候选沿用其版本检查。确认在执行前持久标记executing，重复确认不重放。崩溃或租约过期时将未确认结果标为uncertain，提示先查询实际业务状态，禁止自动重做。会话运行状态持久化，刷新可轮询恢复，失败保留已完成消息。

兼容现有chat/completions模型服务，使用原生工具调用。DeepSeek关闭thinking模式，保留模型生成的调用与tool_call_id配对。模型/HTTP错误不回显上游响应或凭据。测试用本地假供应商验证协议，真实配置仅做一次明确禁止读取小说及执行工具的最小连通测试。
