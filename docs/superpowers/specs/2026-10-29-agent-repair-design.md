# Agent 修复候选与作者确认

用户已确认沿“质检报告 → 修改候选 → 作者确认 → 自动复验”继续开发。本轮在现有 agent、preflight 和 world 草稿流程中实现首个切片，由 root 独立执行。

## 范围

复用当前版本路线体检报告，生成可持久保存的规则修改候选。首期只接受已有 guidance 的 gate-trap 与 weight 修改；不添加带占位正文的引导卡，不自动写作。没有支持的修改时明确提示作者手动处理。候选独立于监督轮询，用户主动生成，无模型费用。

候选包含草稿 ID、基础版本、目标结局、报告时间、精确修改前后值、40 个相同种子下的前后验证摘要。候选生成不会修改草稿。相同草稿版本和目标结局只生成一份，刷新和重复请求可恢复。

## 确认与一致性

作者可确认或驳回。确认时重新读取当前草稿，检查版本，重新运行内容体检与模拟，再在同一个 SQLite 事务中保存新草稿、最新体检报告和候选的 applied 状态。不得出现“草稿已改、候选仍待确认”的部分写入。重复确认不重复增加版本；驳回不改草稿，已应用候选不能驳回。

只允许目标结局的随机到达率提高、无新增 lint 错误、原先通过的 G 检查仍通过且死路数不增加的候选应用。40 种子验证是有限样本，不是完整平衡或可达性证明。阻断原因直接展示；检查执行失败或版本冲突不写回。异步验证期间草稿变化，也须拒绝保存。

## 结构和界面

Agent 应用服务只依赖草稿、体检、候选仓储与事务端口。公共 index.ts 输出服务和 SQLite 适配，HTTP/MCP 共用命令。复用 preflight 的离线检查实现，不另写模拟或游戏规则。

在世界草稿的发布前体检下增加“Agent 修复候选”：生成、查看差异与验证结果、确认应用并复验、驳回。未保存编辑时禁用写入操作。请求期间锁定编辑区，草稿切换不接收旧请求结果。沿用现有 DESIGN_SYSTEM 的紧凑样式和中文优先文案。

## 验收

行为测试覆盖生成不修改、旧报告拒绝、仅支持规则白名单、效果无提升拒绝、新错误/退步拒绝、作者驳回、重复应用、版本冲突（包括验证期间）、事务失败回滚、重启恢复。实际 fixture 验证路线提升；HTTP/MCP 同一候选状态闭环；浏览器检查可操作入口。完整 verify 通过，不改变已发布版本、存档、模型配置或真实任务。
