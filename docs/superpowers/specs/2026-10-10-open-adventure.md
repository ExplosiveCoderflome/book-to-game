# 小范围开放冒险首版

用户已确认开放游戏复审方案并于本轮授权开发，随后明确批准两名 gpt-6.1-sol 子代理分别承担前端与世界/存档规则。沿用 Node24/TypeScript/Express/React/SQLite，不改旧小说项目，不改已有分支运行时。

闭环：导入小说 → 选择章节、玩家身份、忠实/分歧策略 → 持久化分析和生成世界草案 → 作者查看/编辑开局、规则、行动及来源 → 校验发布 → 建立开放冒险存档 → 多策略行动、事件推进、持续后果 → 恢复与结局。首版通过建议行动验证规则，自由文本留在行动解释层后续实现，不声称无限自由行动。

合同在 packages/contracts/src/world.ts。世界为 schemaVersion=1/mode=open 的固定发布包，包含3–12地点、布尔事实（物品/线索/关系/事件）、NPC初始位置与私有目标/已知事实、行动、一次性事件与条件结局。所有条件为AND，效果为受限数据，无脚本执行。行动有可见条件、执行条件、耗时与风险；事件按数组顺序反复扫描直至没有新增触发，每个事件每存档至多一次；结局按数组顺序取首个匹配。行动后先事件后结局，在时限处达成结局优先于超时结局。初始状态也结算事件与结局。turn计成功行动次数，elapsed计耗时，刷新/无效行动不推进。

模型只在改编阶段生成声明式世界，游玩不调用模型。状态保存事实真值、玩家已知事实集合、NPC位置与已知集合、已执行一次性行动和事件、历史与结局。NPC知情只是事实ID集合，规则读取当前真值；本版不模拟误信/遗忘。世界文本公开部分必须由作者审阅避免剧透；玩家DTO不暴露隐藏事实、私有目标、未触发事件、条件或效果。作者token仍有完整编辑权限，本阶段没有玩家账户隔离。

worlds模块拥有草稿、校验与不可变发布；adventure-sessions拥有规则执行及事务存档，依赖只读发布端口。存档固定发布版本，expectedTurn/requestId保护陈旧请求和重复执行。状态与动作重放结果同事务，重放先于回合检查。来源证据必须位于世界选择的章节中；图校验仅保证引用/潜在连通，不冒称证明所有策略可解。

generation复用队列、租约、断点；添加可选mode/chapterIds/playerRole/canonPolicy，老任务默认story。选择范围须属于来源且不重复，章节顺序按原文；仅分析范围内章节，原始证据ID保持。成功open任务draftId指向世界草稿，前端按mode导航。失败重试复用已完成分析。生成世界章节范围必须与任务一致。

HTTP/MCP共用命令：world drafts CRUD/validate/publish、revisions list、adventures start/list/get/act。原有端点和工具保持兼容。root拥有合同、app组合、HTTP/MCP、generation/model和示例；runtime代理只写worlds/adventure-sessions及其测试；frontend代理只写apps/web（根合同不可改）。

验收：原创渡口样例至少三种策略到达目标且留下不同事实；NPC隐藏知识不泄漏；时间事件只触发一次；不满足条件的操作不消耗时间；存档持久化/固定版本/重复动作/冲突/事务回滚；选择章节只发送指定正文；真实MCP和HTTP共享状态；生产启动及浏览器跑通。外部模型用本地测试服务替代，不读取用户真实凭据或声称文学质量验收。

集成补充：保留系统行动 ID `__wait__`，非结束状态可等待一单位时间，按同一事件/结局规则结算，避免无行动可用时无法推进。试玩页突出最近一次行动结果。世界草稿有未保存编辑时，禁止切换草稿、跳入另一任务的世界草稿或断开；页面刷新/离开提供提醒。复杂行动、条件和效果当前使用高级 JSON 编辑，基础开局字段有表单。
