# 首个可用版本实施计划

设计依据：[首期设计](../specs/2026-10-10-foundation.md)。本轮已获用户开发与多名 gpt-6.1-sol 子代理授权。

1. 固定 contracts 与应用接口，建立单仓库、共享 DTO、错误类型和架构边界。
2. sources 先写字节解码/来源稳定性/旧项目 JSON 测试，观察失败后实现纯解析器、仓储端口和 SQLite 适配器。
3. games/sessions 先写无效图、发布不可变、陈旧请求和重复动作测试，再实现规则与事务仓储。
4. generation 先测分块任务、失败重试、租约恢复、取消与幂等创建，再实现 SQLite 任务持久化和可配置模型适配器。
5. HTTP 与 MCP 注入同一个 Workbench；通过真实 HTTP/MCP 客户端验证鉴权与共享流程。
6. React 工作台：导入、来源预览、生成进度、草稿编辑与发布、试玩/恢复。明确尚未启用的模式和模型未配置状态。
7. 增加架构检查、示例、使用说明、MCP 与薄 Skill 接入说明；执行 npm run verify，记录实测结果和限制。

## 分工

root：共享合同、SQLite 初始化、generation、模型、HTTP/MCP、集成验证与项目记录。
frontend：仅 apps/web；sources：仅 sources 和对应测试；games：仅 games/sessions 和对应测试。
所有代理不得再委派，不修改其他负责人文件、根依赖或中央主记录。

## 验收

真实 SQLite 完成导入、发布、重启恢复和幂等选择。可用示例通过相同入口操作，测试替身只替代外部模型。生产网页构建成功；MCP 客户端可发现工具、导入、提交和校验草稿、发布、试玩。没有配置凭据时不声称真实模型调用已验证。

2026-10-10：本计划首期内容已实现并完成本地验收，见 [验收记录](../../verification.md)。真实模型质量验收作为后续工作保留。
