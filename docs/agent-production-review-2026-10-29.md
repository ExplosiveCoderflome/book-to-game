# Agent 制作审阅衔接 · 2026-10-29

## 解决的问题

原有对话能创建制作任务、重写单元和提出修复候选，但读取完整任务/世界时，较大的规划、地图和正文会越过16000字符回执上限。模型被告知“缩小读取范围”，却没有相应工具。此外，确认规划的原接口需要回传完整 `ProductionPlan`，没有向对话开放，用户只能回到制作面板继续。

## 本轮实现

- 共用应用命令 `read_job`、`read_world_draft`：摘要、JSON字段路径、集合分页、长文本分页、可继续读取的大字段目录；每页保留任务时间或草稿版本。小规则对象保留完整结构，避免将片段JSON误认为完整文档。
- 共用 `check_job_plan`：以业务ID检查已存规划，复用现有规则与路线检查，不新增模拟器或模型调用。
- 共用 `approve_saved_production_plan`：只确认已存规划并排队正文；带审阅时任务时间，作者确认卡明确角色、玩法体量、路线和后续模型费用。既有完整规划编辑/确认接口保留。
- 确认时和仓储事务中检查任务时间。仍复用现有聊天持久操作、重复确认回执和不确定状态处理，不增加另一套确认机制。
- 对话白名单切换至分段读取；任务写入、发布返回简短业务回执，正文按需读。更新助手工作流提示。
- 不改变已发布世界、玩家存档、运行时规则和用户模型配置。

## 验证范围

新增测试覆盖分页无丢项、深路径回执大小、长文本完整恢复、路径错误、只读不改任务、规划规则阻断、审阅后版本变化、事务内版本冲突、确认后精确保留规划。

集成测试使用本地HTTP模型供应商调用真实工具：读取任务、审阅人物和路线、检查规划、形成待确认卡、HTTP确认、MCP重复确认、worker复用规划并保存第一段正文检查点；模拟后续写作中断，不伪造成品。另验证任务取消后旧确认不能开写，以及HTTP/MCP分段世界读取。

没有真实模型调用或新增付费生成，未改 `docs/samples/shoudeng/*`。

本机另用《武林外传》已生成任务快照做只读复核：72个正文单元通过15页目录全部精确恢复，最大数据页2831字符、任务摘要1235字符，均低于16000字符回执上限。证据为Git忽略的 `data/verification/agent-read-real-result.json`；不重新生成、不改草稿或存档。

`npm run verify` 退出码0：416项服务端/脚本测试、126项前端测试、1项构建后启动测试，共543项通过；架构检查（347个源文件）、类型检查、作者工作台和单文件播放器构建通过。新增8项行为/集成测试。完整日志位于 `data/verification/agent-review-verify.log`。构建仍有既有的大chunk体积警告，未在本切片改打包策略。
