# 《武林外传：同福旧账》角色扮演验收

用户确认：以电视剧为背景，玩家扮演白展堂，隐瞒旧身份并保护客栈；先开发，真实模型调用待补充 API 配置后进行。

## 输入与内容边界

可复用输入是 [`examples/wulin-waizhuan.production.json`](../examples/wulin-waizhuan.production.json)。这是创作简报，不是生成好的游戏，也不是原剧剧本。

人物与地点依据央视的[节目介绍](https://tv.cctv.com/v/vs4/VIDA1354531513618469.html)及[角色介绍](https://ent.cctv.com/20070618/102738_1.shtml)。七侠镇、同福客栈和原剧人物作为既有设定；假当票、修桥义卖、住客簿盘查及相关对话、事件、结局均为原创测试情境。

白展堂有点穴本领和需要隐瞒的过去，既想保护佟湘玉与伙计，也不愿重新卷入盗业。角色不能被改写成不认识众人的新伙计。佟湘玉、郭芙蓉、吕秀才、李大嘴、莫小贝、捕快各有诉求和行为边界；帮助需要条件，不是点一次就无条件给奖励。

## 必须实际玩出的东西

| 维度 | 验收要求 |
|---|---|
| 扮演身份 | 开局明确玩家是白展堂，行动和称呼符合原有关系；不再出现另一个同行白展堂 NPC |
| 日常循环 | 跑堂/经营、休息、交谈、调查能反复进行；钱、体力、信任、嫌疑至少四种资源有来源与消耗 |
| 选择后果 | 花钱、说谎、透露线索、请人帮忙留下持续变化；选项费用、条件、结果与存档一致 |
| 地点与人物 | 至少三个连通地点、三个有目标的配角；无路可走时有恢复/等待或明确收束 |
| 三条策略 | 合作查假票、交出有限证据、通过人情谈判至少三条可区别的通关策略；不是换文案的同一结局 |
| 失败 | 身份暴露、客栈失信或期限耗尽有明确后果；玩家能理解为什么失败 |
| 内容 | S 档至少25张卡、8张可重复事件、15,000字；正文与结果具体，不用万能模板句撑数 |
| 交付 | 发布后导出 HTML；断网开局、行动、读档、走到结局；读档保持人物关系、事实与随机状态 |

快速模拟只排查明显死路和未覆盖结局，不能证明剧情好玩，也不能把“未覆盖”说成“不可达”。最终还要逐条手走三条策略和一次失败路线，并由用户评价人物与取舍。

## 本次开发

- 改编生成页默认提供“制作角色扮演游戏”；保留原作快速改编。
- 支持直接填写设定和角色，也可附加已导入资料，不必先准备一本小说。
- 先生成 `ProductionPlan`，包含人物边界、关系、路线以及可执行的世界规则；保存后等待审阅，可修改再确认。
- 确认后逐个地点、剧情卡、固定行动、结局（含期限耗尽）与事件写正文。概率行动分别检查成功和失败文案，避免把规划占位句带给玩家。文案响应只含正文和结果；规则、条件、费用和地点连接来自已确认规划。
- 每个单元完成即存入原有任务仓储；失败、取消或重启后复用已完成分析、规划和正文，不重复整局生成。
- 确认前不会生成正文；取消再重试也必须继续等待规划确认。
- 确定性组装草稿，自动运行对应档位 lint 和6种策略×20种子的快速试玩。体检有问题仍保留草稿供审改，发布继续受 lint 门禁约束。
- 普通市井题材的模拟优先识别银两、信任等资源，报告行动耗时，不把无月历游戏写成“几个月/只修炼”。
- 完成或中断的写作任务可选择一个正文单元，附作者意见重写；其他正文和已确认玩法复用，重新体检并生成新草稿，原草稿保留。修订中断后继续保留意见与原文。

这不是完整 S3：卡片筛选与锁定编辑器、预算与实际 token 账单、并发写作、自动平衡修复尚未实现。

## API 与运行

照常运行 `npm run dev`，在“改编生成 → 制作角色扮演游戏”使用白展堂简报。真实调用沿用模型设置，不增加密钥文件或把凭据放进前端。

HTTP 与 MCP 使用相同应用命令：

| HTTP | MCP | 行为 |
|---|---|---|
| `POST /api/production/jobs` | `create_production_job` | `{requestId, brief, sourceId?}` 创建制作任务；相同请求重复提交不会重复创建来源 |
| `GET /api/jobs/:id` | `get_job` | 读取阶段、已保存正文、规划与报告 |
| `POST /api/jobs/:id/approve-plan` | `approve_production_plan` | `{plan}` 确认经过审阅的规划并继续写作 |
| `POST /api/jobs/:id/rewrite-unit` | `rewrite_production_unit` | `{unitKey, direction}` 只修订单段，保留原草稿 |
| `POST /api/jobs/:id/retry` | `retry_job` | 从断点继续 |

生成的草稿继续使用原有世界草稿、试玩、发布和导出接口。
